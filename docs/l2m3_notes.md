# L2M3 (Large Language Model MOF Miner) — 공부 

> Kang, Y.; Lee, W.; Bae, T.; Han, S.; Jang, H.; Kim, J. "Harnessing Large Language
> Models to Collect and Analyze Metal−Organic Framework Property Data Set"
> *J. Am. Chem. Soc.* 2025, 147, 3943−3958. (KAIST 김지한 교수 연구실)
>
> MOF SDL OS(실험 자동화)와는 다른 방향 —
> **"이미 발표된 논문에서 지식을 추출"**하는 시스템. virtual MOF SDL
> (문헌 → LLM 추출 → 지식그래프 → Prefect 실행)과 목적이 겹치는 부분이 있어 자세히 정리함.

---

## 1. 문제의식과 규모

MOF 관련 논문이 이미 4만 편 넘게 쌓여있는데, 그 안의 **합성 조건**과 **물성 데이터**는
전부 비정형 텍스트(본문, 표)에 갇혀있어서 기계가 못 씀. LLM으로 이 데이터를 자동
추출해서, MOF 연구자들이 바로 쓸 수 있는 대규모 데이터베이스를 만든 것이 이 논문의 목표.

- 4개 출판사(ACS, Elsevier, RSC, Springer)에서 **41,681편** 수집
- 최종적으로 **39,476편**에서 합성 조건 + 물성 데이터 추출 성공
- **32개**의 명확히 정의된 물성 + 더 넓은 범주의 추가 물성들
- 합성 과정을 **21개 범주**로 분류

## 2. 시스템 아키텍처 (Figure 1)

두 개의 큰 에이전트로 구성:

### (A) Data Extraction Agent — 3개 세부 에이전트
1. **Table Agent** — 논문 안의 표를 처리
2. **Synthesis Condition Agent** — 합성 조건이 적힌 텍스트를 처리
3. **Property Agent** — 물성이 적힌 텍스트를 처리

### (B) Data Organizing Agent
추출된 데이터를 CCDC(Cambridge Crystallographic Data Centre) 데이터베이스와 매칭해서,
같은 물질에 대한 데이터를 하나로 통합.

### 표 처리 3단계 (Figure 1b)
1. **Categorization**: 표를 "물성 표" / "결정 정보 표" / "기타"로 분류
2. **Inclusion**: 그 표 안에 정확히 어떤 정보(LCD, PLD, Td 등)가 있는지 판단
3. **Extraction**: 실제 값을 JSON으로 추출 — 예: `{'LCD': {'value': 5.5, 'unit': 'Å'}}`

### 텍스트 처리 3단계 (Figure 1c)
표와 동일한 구조. 텍스트 문단이 "합성 조건인지/물성인지/둘 다 아닌지" 먼저 분류하고,
각각 다른 전문 에이전트로 라우팅.

**왜 3단계로 쪼갰는가**: 한 번에 다 추출하려면 프롬프트가 너무 길어져서 정확도가
떨어지고 비용도 늘어남. 문제를 작게 쪼개서 순차 처리(chain of LLM agents)하는 방식으로
이를 회피.

## 3. 적응형 프롬프트 (Adaptable LLM Prompt) — Figure 2, 9

이 논문의 핵심 기술적 트릭. 추출 에이전트의 프롬프트가 고정되어 있지 않고, **앞
단계(categorization/inclusion) 결과에 따라 동적으로 재구성**됨.

- System Prompt(역할 지시) + Format Prompt(JSON 출력 형식) + Example(예시)을 조합해서
  최종 프롬프트 생성
- 예: "기공 부피(pore volume)"가 물질마다 여러 종류(micropore, total pore 등)로 표현될
  수 있다는 걸 프롬프트 안의 "Information" 섹션으로 미리 알려줘서 혼동 방지

Figure 9의 실제 프롬프트 예시를 보면 규칙이 매우 세세함:
- "확실하지 않으면 'I do not know'라고 답하라"
- "숫자는 특정 형식으로 써라"
- "예시에 없는 정보는 지어내지 마라"

→ 이런 명시적 규칙들이 **환각(hallucination)을 줄이는 실질적인 방법**.

## 4. 정확도 평가 (Table 1)

150개 논문 샘플로 검증:

| 데이터 타입 | Categorization F1 | Inclusion F1 | Extraction F1 |
|---|---|---|---|
| 합성(Synthesis) | 0.99 | 0.94 | 0.93 |
| 물성(Property) | 0.96 | 0.98 | 0.93 |
| 표(Table) | 1.00 | 1.00 | 1.00 |

- **표가 제일 정확한 이유**: 구조가 명확해서(행/열이 정해짐) 텍스트보다 파싱하기 쉬움
- **합성 조건 추출 정확도가 살짝 낮은 이유**: "solvothermal synthesis"와 "chemical
  synthesis"처럼 비슷한 합성법끼리 구분이 애매한 경우가 있음
- **multi-LLM(에이전트 나누기) vs single-LLM**: multi-LLM이 정확도와 비용 둘 다 우월함을
  실증 (Note S5) — "왜 하나의 거대한 프롬프트로 안 하고 여러 전문 에이전트로 쪼갰는지"에
  대한 근거

## 5. 데이터 마이닝 통계 결과 (Figure 3, 4)

- 제일 자주 나오는 물성: **화학식, 격자 상수(lattice parameter), 밀도** — 합성 조건 추정에
  꼭 필요한 정보라 자주 보고됨
- 시뮬레이션으로 구하기 어려운 물성(**결정 크기, 분해 온도, 수율**)도 상당량 확보 —
  계산으로 못 얻는 걸 실험 문헌에서 뽑아온 것이 이 데이터셋의 진짜 가치
- 표면적 측정: **BET 방법이 78.4%**로 압도적
- 기공 부피 측정: **N2를 프로브로 쓴 게 92.5%**

## 6. 시뮬레이션 vs 실험 데이터의 괴리 (Table 2, Figure 4c~f)

**실험 설계**: 밀도(density) 예측 모델을 실험 데이터로 학습시킨 것 vs 시뮬레이션
데이터로 학습시킨 것을 비교 (테스트는 항상 실험 데이터).

| 모델 | 실험 데이터 학습 (R²) | 시뮬레이션 데이터 학습 (R²) |
|---|---|---|
| XGBoost | 0.803 | 0.495 |
| CGCNN (그래프 기반) | 0.815 | 0.400 |
| MOFTransformer (멀티모달) | **0.892** | 0.380 |

**놀라운 발견**: 더 복잡한 모델(MOFTransformer)일수록 실험 데이터 학습 시 성능이 더
좋아지는데, 시뮬레이션 데이터 학습 시엔 오히려 더 나빠짐. 복잡한 모델은 학습 데이터의
특성을 더 세밀하게 학습하는데, 시뮬레이션은 "이상적인(defect-free) 구조"를 가정하니까
실제 지저분한 실험 데이터와 안 맞는 패턴을 학습해버리기 때문.

## 7. SHAP 분석 딥다이브 — 괴리의 원인을 찾다 (Figure 6)

### SHAP이 뭔지
**SHapley Additive exPlanations**. 머신러닝 모델이 예측할 때 각 입력 변수(feature)가
얼마나, 어느 방향으로 기여했는지를 숫자로 보여주는 기법. 게임이론의 Shapley Value에서
따온 개념 — 여러 사람이 팀으로 일해서 낸 결과를, "각자가 정확히 얼마만큼 기여했는지"
공정하게 나눠서 계산하는 방식. 모델을 블랙박스로 두지 않고, 예측 하나하나를 "이 변수가
+0.3만큼 밀었고, 저 변수가 -0.1만큼 당겼다"는 식으로 분해해서 설명해줌.

### 무엇을 예측하는 모델에 SHAP을 적용했는가
예측 대상: **`Dexp − Dideal`** (실험으로 측정된 밀도 − 이상적인 시뮬레이션 구조의 밀도).
즉 "이 MOF가 실제로 시뮬레이션보다 얼마나 무거운가"를 예측하는 모델. 30,892개 데이터로
학습.

### Figure 6a — 상위 15개 중요 변수 (3개 그룹)
- **Metal cluster(금속 클러스터) 관련**: electron affinity(전자친화도), Cu fraction
- **Organic linker(유기 리간드) 관련**: N/O/Cl fraction, MaxAbsPartialCharge, MolMR
- **Global(전체 구조) 관련**: mean AtomicRadius, mean AtomicWeight

**해석**: 이 변수들은 전부 "이 MOF가 게스트 분자(잔류 물질)와 얼마나 강하게 상호작용할지"를
결정하는 요인. 예를 들어 부분전하가 크면 극성 용매(물, DMF 등)를 강하게 붙잡아두고,
질소/산소가 많으면 수소결합을 잘 형성해서 물 분자를 놓아주기 어려워짐.

### Figure 6b~d — 잔류 물질(residual species)이 진짜 원인이라는 증거
1. **6b**: CoREMOF(이상 구조, 잔류물 제거)와 실제 CSD 구조(잔류물 그대로)를 나란히 비교한
   3D 구조 이미지. 실제 구조에는 격자 사이사이에 작은 분자들이 끼어있는 게 육안으로 보임.
2. **6c**: 가장 흔한 잔류 물질 50개 순위표. **물(H2O)이 압도적 1위(12,365회)**, 그다음
   MeCN, DMF, MeOH, DCM. 4가지 타입: Solvent(용매), Modulator(결정 크기/형태 조절제),
   Counter ion(금속 전구체에서 온 반대이온), Etc.
3. **6d**: **잔류 물질의 분자량과 밀도 차이 사이 상관계수 0.64** (꽤 강한 양의 상관관계).
   무거운 잔류 물질(반대이온 등)일수록 밀도 차이를 더 크게 만듦. 파란 점(Modulator)과
   초록 점(Etc)이 추세선보다 위에 있는 게, "무거운 반대이온이 낀 경우 밀도 차이가 특히
   크다"는 걸 시각적으로 보여줌.

### 왜 이 분석이 똑똑한 접근인가
"시뮬레이션과 실험이 다르다"에서 끝내지 않고, **SHAP → 잔류물질 종류 분석 → 분자량
상관관계**까지 이어지는 3단 논증으로 원인을 구조적으로 증명. 단순 데이터 마이닝
논문보다 한 단계 더 나간 부분.

## 8. 파인튜닝 방법론 딥다이브 — 두 개의 서로 다른 파인튜닝

### (A) 데이터 추출용 파인튜닝 (Categorization + Inclusion 단계)

- **대상 모델**: GPT-3.5-turbo (비용 때문으로 추정)
- **학습 데이터**: Categorization용 723개, Inclusion용 681개 예시. GPT-4로 먼저 프롬프트
  엔지니어링해서 예시를 만들고, 사람이 검토(human review)해서 확정
  → 전략: "고품질 모델(GPT-4)로 정답 예시를 만들고, 그 예시로 저렴한 모델(GPT-3.5)을
  훈련시켜서 대량 처리에 쓴다"
- **Extraction 단계는 왜 파인튜닝 안 했는가**: "the project's advanced stage and budget
  considerations"(프로젝트 진행 단계와 예산 문제)라고 명시. 대신 GPT-4를 프롬프트
  엔지니어링으로 그대로 사용, 8000토큰 한도 초과 시 GPT-3.5-turbo-0125가 보조 투입
- **GPT vs Llama**: 오픈소스 모델(Llama)도 시도했으나 정확도가 더 낮아서 GPT 최종 선택
  (Note S10)
- **데이터 양과 정확도**: "F1 score of data mining increases as the number of fine-tune
  data sets increases" — 파인튜닝 데이터가 많을수록 정확도 향상, 성능과 효율의 균형점을
  고려해 현재 크기로 결정
- **비용 효과**: 파인튜닝이 프롬프트 엔지니어링보다 **계산 비용 약 95% 절감** (Figure S13)

**트레이드오프 요약**: 파인튜닝은 초기에 학습 데이터 만드는 수고가 들지만, 이후 대량
처리(4만 편!) 시 훨씬 저렴. 프롬프트 엔지니어링은 초기 비용 없지만 매번 긴 프롬프트를
보내야 해서 대량 처리 시 누적 비용이 커짐.

### (B) 합성 조건 추천 시스템용 파인튜닝 (Figure 7, 완전히 다른 작업)

데이터 **추출**이 아니라 **생성(추천)**을 위한 파인튜닝:
- **목적**: "이 전구체들로 뭘 합성할 수 있어?"라는 질문에 합성 조건을 생성
- **모델**: GPT-4o와 GPT-3.5-turbo 둘 다 파인튜닝
- **데이터**: 60,735개 합성 조건 중 CCDC 매칭 + 전구체 5회 이상 사용된 9,044개를
  3:1로 train/test 분할
- **결과**: 두 모델 다 **0.83점**으로 거의 동일 → "모델 종류보다 데이터 양이 성능을 더
  좌우한다"는 결론
- **벤치마크**: Fine-tuning(0.83) > Few-shot 프롬프트(n=100, 약 0.7) > Zero-shot(약
  0.4~0.5, 랜덤과 비슷) > Rule-based(제일 낮음)
- **시간 일반화 테스트 (Figure 7d)**: 오래된 데이터로 학습해도 최근 5년치 합성 조건을 잘
  예측하는지 테스트 → 최근으로 갈수록 정확도가 오히려 향상 (전구체가 다양해지고, 과거
  트렌드가 최근 조건에 강하게 영향을 주기 때문으로 해석)

### 두 파인튜닝의 공통 설계 철학
두 경우 다 "파인튜닝이 프롬프트 엔지니어링보다 일관되게 우월"하다는 결론. 근데 재미있는
차이: 추출 작업(A)에서는 GPT-3.5 파인튜닝만으로 충분했는데, Extraction 자체(가장 복잡한
최종 단계)는 오히려 파인튜닝을 포기하고 GPT-4 프롬프트 엔지니어링으로 감.
→ **"작업이 단순·반복적일수록 작은 모델을 파인튜닝하는 게 이득, 작업이 복잡하고 매번
다른 맥락이 필요할수록 크고 유연한 모델을 프롬프트로 유도하는 게 낫다"**는 실용적 판단
기준.

## 9. ChatMOF 통합 (Figure 8)

L2M3 데이터베이스를 **ChatMOF**(대화형 챗봇)에 연결한 사례. 예: "MIL-120의 합성 정보를
알려줘"라고 물으면:
1. **Material Finder** 툴이 "MIL-120"이라는 이름을 CCDC 코드(BUSQIQ)로 변환
2. **Synthesis Condition Searcher** 툴이 그 코드로 DB에서 합성법 검색
3. 최종 답변으로 5단계 합성 절차(수열합성, pH 조정, 여과, 세척, 건조) 생성

→ L2M3는 단순 데이터베이스가 아니라, **AI 에이전트가 도구(tool)로 활용할 수 있는 형태**로
설계됨.

## 10. 방법론 세부사항 (Methods 섹션)

- **논문 수집**: XML/HTML 형식 다운로드, 출판사 승인 받아 저작권 준수
- **CSD 데이터베이스 통합**: DOI로 논문과 CSD 연결, 결정 구조 파일(CIF 등) 확보
- **구조 정제**: P1 대칭으로 통일, floating solvent 제거(단 binding ligand는 유지),
  원자 간 거리 1Å 미만인 비정상 구조는 제외
- **Zeo++ 소프트웨어**로 밀도·기공부피·표면적 계산 (probe radius 1.82)

## 12. 용어 정리

- **CCDC / CSD**: 전 세계 결정 구조 정보를 모아둔 데이터베이스 (Cambridge
  Crystallographic Data Centre / Cambridge Structural Database)
- **CoREMOF**: 계산에 적합하도록 잔류 물질을 제거한 "이상적인" MOF 구조 데이터셋
- **SHAP (SHapley Additive exPlanations)**: 모델의 각 예측에서 어떤 입력 변수가 얼마나
  기여했는지 게임이론(Shapley Value) 기반으로 분해해서 설명하는 기법
- **BET / Langmuir**: 표면적을 측정하는 두 가지 다른 계산 방법 (기체 흡착량 기반)
- **Fine-tuning vs Prompt Engineering**: 파인튜닝은 모델 자체를 데이터로 재학습시키는 것,
  프롬프트 엔지니어링은 모델은 그대로 두고 입력 지시문만 정교하게 짜는 것
- **F1 Score**: Precision(정밀도)과 Recall(재현율)의 조화평균
- **R² Score**: 모델 예측이 실제 값의 분산을 얼마나 잘 설명하는지 나타내는 지표 (1에
  가까울수록 좋음)
- **CGCNN / MOFTransformer**: 각각 그래프 신경망 기반, 멀티모달 트랜스포머 기반의 MOF
  물성 예측 모델
